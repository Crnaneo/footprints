# 足迹 Footprint

在本机保存、浏览和导出飞机、铁路及自定义轨迹。网页界面与 SQLite 数据库均运行在本机，服务地址为 `http://127.0.0.1:8765`。

已实现 CSV 导入与导出、全部原始轨迹点地图、日期与类型筛选、关键词搜索、轨迹详情与逐点查看、按日高度与速度图、当期铁路区间导入，以及 Flightradar24 航班查询接口和本地密钥配置。

## 使用

macOS 上双击项目中的 `start.command`。首次运行会安装依赖并生成前端；随后启动服务并打开浏览器。终端窗口保持打开，按 Ctrl+C 停止。

默认 8765 端口被占用时，启动脚本会改用 8766。已有足迹服务时会直接复用。终端会打印实际访问地址；也可用 `FOOTPRINT_PORT` 指定端口。

也可在项目目录运行：

```sh
npm start
```

新机器首次安装需要 Python 3.11 或更新版本、Node.js 22.12 或更新版本：

```sh
./scripts/setup.sh
./start.command
```

足迹数据库位于 `data/footprint.sqlite3`。API 密钥位于 `data/settings.json`，仅当前用户可读写；上传的源文件按导入结果另存于本地。备份时停止应用后复制 `data` 目录。CSV 可用于单条或全部轨迹的便携备份；CSV 不包含 API 密钥。不要把包含个人行程和密钥的 `data` 目录公开。

## 导入轨迹

默认导入、导出和模板采用一生足迹的 11 列格式，列名与顺序如下：

```csv
dataTime,locType,longitude,latitude,heading,accuracy,speed,distance,isBackForeground,stepType,altitude
1790899200,1,116.372000,39.863000,0,10,12.5,0,1,0,20
```

`dataTime` 为 Unix 秒；经纬度默认 WGS84；`speed` 为米/秒，界面乘以 3.6 显示 km/h；`altitude` 为米。原始 speed=-1 表示没有速度记录，界面显示空值；0 速度、负海拔、重复时间戳均保留。未确定含义的 distance、locType 及状态字段按原样保存，不用于生成未实测的值。

一生足迹备份按北京时间（UTC+8）自动分日并按时间排序，CSV 不需要预先整理。断开超过 15 分钟的定位间隔与明显跳变；原始行顺序和所有数值字面值另行保存，WGS84 备份导出时原样还原。地图通过本机点瓦片显示全部原始点，不连线、不抽样；选中某日后加载该日测量详情供查看和绘图。列表使用轻量预览，不影响地图与导出。每次备份最大 512 MB、5,000,000 个点，单日最多 200,000 点。完整校验后整批保存，任一错误均不部分写入。同一文件与坐标系重复上传不重复添加；曾删除日记录时重新上传会恢复缺失日期。

导出 CSV 使用 UTF-8 BOM。默认格式没有车次、来源或分段元数据，其他来源未提供的字段为空或 -1，不填造时间和测量值。无 dataTime 的点导入时需要指定日期。导出的坐标统一为 WGS84；若原文件为 GCJ-02，导入时必须选择 GCJ-02，保存原始文件及坐标，导出时转换为 WGS84。原 WGS84 一生足迹 CSV 的全部 11 列可无损往返。

仍支持旧的通用点列及 FR24 CSV：经纬度必填，时间、速度、高度可为空；通用格式速度为 km/h、高度为米；FR24 的英尺与节会自动转换。可自定义列匹配；`trip_id` / `track_id` 分组，`segment_id` 断线，`sequence` 排序。通用导入上限 100 MB、200,000 点、1,000 条记录。设置中的“扩展 CSV”保留车次、分段及来源备注，但完整保存一生足迹全部原始字段应使用默认 11 列 CSV 或复制本地 data 目录。

地图范围在导入时按全部坐标预计算，打开地图不再扫描全库点。瓦片使用 96 MiB 有界缓存和预压缩；导入、删除自动更新数据版本并使缓存失效。重复 HTTP 请求使用 ETag 校验，未变更返回 304。密集点详情仅在点击时读取；底图切换保留已有点源，选中记录只更新必要的样式与视野。

## 铁路足迹区间

地图右上“铁路足迹”按线路汇总已到达区间，线路从上至下按全部已乘坐区间的里程之和降序排列，标题显示该总里程；线路内部区间仍按下行排序。可搜索线路、目录别名或车站。客运站、货运站、线路所都可作为边界；以客运电报码或 OSM 身份连接同一站点。所有共享边界的区间合并，站场分支也可连入同一显示区间。参考片段先用共享站点校准方向，已到达区间再沿实际连接的站间图排序，避免短轴投影产生倒序和交错。重复参考边与回路只计一次。已知车站中心偏离轨道的距离计入边界误差；近站 2 公里内的端点归站。同名、同类非客运节点在 50 米内合并；同名线路所在 2 公里内且共享线路声明、没有冲突官方标识时也采用同一身份。

已到达采用两种判定之一：**相邻铁路站点**间，连续覆盖严格超过全段 10%；或汇总所有日期的已归属轨迹点，密度严格超过每 10 公里 1 个点，而且任意相邻客运站之间都有点。长度不能跨轨迹断档拼接。密度只看点的存在，不要求同一记录、同一记录段或连续移动，静止/低速点也计入；线路归属仍需先经过几何和定位质量判断。候选边界切入客运站间时，其内部的客运站间局部也不能完全无点。

连续两站之间存在换线节点，且记录仅在节点一侧时，不外推到另一侧没有记录的远端站。以当前站间和包含它的客运站间共同检查两侧证据，不借用下一个客运区间证明上一段尾部，也不因内部货运站间断档拆开已有密度证据的客运区间。已有记录进入远端站 2 公里到达范围时，站前节点不能否定该到达。切除后重算剩余密度。属于同一线路的公共几何缺口端点不超过 5 公里时，可按密度连接，缺口只计参考估算里程。

只有共用/近乎重合路段有点的候选，且另一条铁路在共用段外有分布超过 5 公里的点证据、并形成超过 5 公里的有效区间时，不单独计入。页面可展开查看归并候选。相同国内线路编号、物理轨道成员基本包含、显示站点完全包含的目录别名合并展示。不同编号的父子目录只有成员基本包含、显示站点和实际点多重集完全相同时才去重。用户明确排除的线路保存于 `data/rail/excluded-lines.json`，仅影响铁路展示和统计，原始轨迹保留。未借用另一条独立平行铁路的点填补空白。

同线区间从上至下按下行顺序排列；优先采用该线路公里标递增方向，缺少公里标时按线路起终点推定并标注依据，无法核对的方向明确提示。点击区间可展开其中全部可确认的客运站，按下行排列，并显示首次到达日期：本地铁路匹配点距站 2 公里内的最早北京时间记录日；没有近站点则显示“未记录”。这是经过或接近该站的记录，不证明停靠或实际上下车。金山铁路等售票站名录外的客运站通过公开客运资料补充。

导入后后台自动匹配，也可手动重新匹配；轨迹或规则变化时缓存标记需更新。缺少可用边界或证据不满足阈值的候选线路不生成区间。上下行平行轨道归并，站场连接造成的重复折返参考路径进行识别。区间边界与显示里程为概括结果，不表示全段逐米实测；当前站名录与 OSM 资料可能缺少历史车站或线路。

匹配在本机使用缓存的 OpenStreetMap 铁路关系、轨道和车站；递归展开子关系，保留主参考路径外的实际成员支段，排除纯地铁、轻轨、单轨车站作为国铁边界，并纳入有国内编号或已知客运端点但缺少可选运营标签的线路。私人 GPS 不上传。候选轨道检索 250 米，实际接受距离为 `min(90米, max(15米, 3×CSV accuracy))`，无精度字段时上限 90 米。定位误差超过 90 米的点不确认铁路身份，但全部保留在地图和 CSV 中。相邻原始点在 1.8 公里、180 秒内时才参考局部方向；邻线归属结合前后 15 分钟、20 公里内至少 4 个明确点，最高支持至少为次高的 2 倍。保留被抖动方向排除的候选供明确上下文复核，防止普速误归高速。

实测长度另用持续运动记录，至少 8 点及物理覆盖并集 5 公里，短线/联络线为 0.8 公里；往返抖动不累加为长途移动。历史零速度可根据原始位置/时间恢复，仅供计算，不改 CSV。速度 35–380 km/h 等运动约束只限制长度证据；密度不使用这一最低速度条件。高空及飞机来源不用于铁路身份。混合日记录的点前后 5 分钟内，至少 3 个可信点超过 450 km/h 或海拔 6000 m 时，将该点标为飞行上下文，低速起降点也不计铁路密度；同日后续地面记录仍可匹配。cnrail 当前几何存在坐标偏差，未用于直接贴合 GPS。


新增的最终边界规则对合并后起终两端递归执行：1 公里内本区间有效铁路点至少 2 个，或真实半径 1 公里内原始点至少 10 个，且必须有真实到达日期。删除端站后继续检查新端站；只剩单站不计区间。内部无其它线路连接、两端非客运且无已记录的其它线路邻站衔接，不计区间。枢纽 A 的 1 公里内关联铁路有效点 >5、最近非客运站 B 向 A 有本线点时补判 A—B；C—A—B 外侧已有记录，且两侧向 A 有点，或 C/B 均非客运无其它连接时可贯通。补判后仍执行边界校验。完整条件见 [v10 规则](docs/rail-boundary-rules-v10.md)。圆内原始点支撑的首次日期表示接近该站，不证明实际乘坐该线。

铁路足迹支持手动添加线路/区间、编辑两端和删除统计。线路与全部站点、线路所通过输入后点击目录匹配项选择；自动列出区间内客运站与近站首次日期，无记录显示“未记录”。手动维护的线路单独保存，重新匹配不会覆盖，支持撤销、恢复删除及恢复自动统计。手动日期取站点真实半径 1 公里内的原始轨迹，属于接近车站的日期；原始轨迹点和 CSV 不改写。详细操作及备份说明见 [手动维护](docs/rail-manual-editing.md)。

铁路目录和匹配缓存不随仓库分发。准备公共铁路目录：

```sh
.venv/bin/python scripts/download_rail_catalog.py
```

下载并缓存固定全国范围的 OSM 铁路资料及 12306 客运站名录，并通过官方 OSM 节点接口补齐全国线路成员中的线路所等控制点；只查询公共目录，不包含用户坐标。需要网络及足够磁盘空间。当前目录用于中国铁路，境外轨迹仍显示在地图中，但不承诺境外铁路匹配。

## 自动查询

铁路使用 RailGo 数据服务，支持 G、D、C 以及普速车次，实际覆盖取决于来源。输入上车日期、车次及到发站，软件沿来源铁路曲线截取乘车区间，并处理跨夜车次的始发日期。线路数据标注为“沿铁路重建”，没有逐点实测速度或 GPS 时间。历史日期使用当前经由并明确标注。线路接口站点不完整或没有曲线时，按乘车区间的停站顺序逐段匹配本地铁路目录，每两站必须有唯一可用线路。支持 G2082/3 等换号车次输入。RailGo 数据用于非商业个人使用，来源在界面标注。[RailGo 官方服务](https://api.railgo.dev/)

航班在套餐历史范围内按 FR24 → ADS-B（OpenSky / adsb.lol）→ 本地 GPS 查询实际轨迹；超出范围直接从 ADS-B 查起。`FR24_HISTORY_DAYS` 默认 30，可按实际套餐调整。FR24 摘要已查到但轨迹失败时，仍保留当日航班资料，并将 hex 和起降时间传给 ADS-B 查询。注册号自动解析 hex；在线没有实际轨迹或服务暂不可用时，才匹配已有个人 GPS；两者都没有实际轨迹但有航班或飞机资料时，可预览并确认只保存资料，轨迹留空；所有资料也缺失时才返回无数据，不保存固定航线。在线返回多个航段时仍需先选择，输入错误不会静默降级。选择“仅从已有 GPS 恢复”或确认已选本地航段会跳过在线轨迹查询。本地恢复方式：填写航班号、出发日期及两端机场，按当地日期、机场端点（30 km 内）、飞行速度与连续性筛选航段，预览后保存。同日多个匹配必须选择；可填写出发机场当地起飞时间缩小范围。原始 GPS 保留，恢复记录携带来源引用，来源仍在库中时不重复累计里程。已有无轨迹航班可在详情点击“从已有 GPS 恢复轨迹”，补全原记录并保留 ID 和飞机资料。GPS 中缺失的速度与高度仍为空，起降时刻与跑道推断均有标注；同一航班的多个记录区段和符合飞行证据的短时巡航空缺可共同匹配，两端仍须有机场证据，缺失部分保持断线、不插值、不计入观测里程。算法需要覆盖两端机场及足够飞行速度证据，暂不自动匹配零散巡航片段或低速航空器。

航班号和出发日期可自动查询当日执飞机注册号、hex、机型及观测到的机场：FR24 缺少身份资料时，解析 IATA 航司代码（含 `3U`、`6E`、`U2` 等），结合 OpenFlights 航司表和 ADSBDB 呼号别名，在 [MrAirspace 季度 ADS-B 航班索引](https://github.com/MrAirspace/aircraft-flight-schedules)中精确匹配。资料查询与轨迹查询分开：这份索引不包含逐点轨迹，取得 hex 后继续尝试 OpenSky / adsb.lol，最后再匹配本地 GPS。机场、注册号和起飞时间均为选填筛选条件。已提供两端机场和注册号或 hex 时跳过季度索引下载，不要求起飞时间。索引下载期间可点击“终止下载并退出”或右上角关闭按钮，后端停止下载并保留部分文件以便下次续传。固定航线只用于解析呼号，不用于补造历史机场或位置点。

MrAirspace 数据从 2024 年起按季度发布。按航班日期自动发现已发布季度；首次查询会下载约 0.3–1 GB 的 Parquet 文件至 `data/flight_schedules`，显示下载进度并自动继续，后续使用本地 DuckDB 和查询缓存。下载采用文件锁、断点续传、大小和发布方 SHA256 校验，两个本地端口共用缓存；下载等待只轮询索引状态，不反复请求 FR24。首次验证时已缓存 2026 Q1。2026-10-07 实测最新发布为 2026 Q2，Q3 航班尚不能通过该索引匹配；发布目录每六小时刷新。目录或下载不可用时继续其它来源并说明原因。

当索引只包含空中片段而缺少起降机场时，可以用原始本地 GPS 交叉确认：两个 ADS-B 端点必须分别与 GPS 在 120 秒、5 km 内匹配；机场候选必须有 4 km 内且海拔接近机场的低速 GPS 证据，再通过现有本地飞行匹配器的速度、连续性、两端机场和当地出发日期检查。唯一匹配才填入机场，保留来源记录引用和匹配证据，不修改原始 GPS 点；该逻辑不依赖任何具体航班号、注册号或机场。界面明确标注机场来自本地 GPS。

日期候选优先采用已确认的当地出发日期及请求日期内的观测；有当日匹配时不混入相邻日期的未确认片段。起点附近多个机场即使不能确定具体机场，若时区一致仍用于显示观测地当地时间。仅剩跨日、不完整观测时明确提示出发日期未确认，供用户核对，避免把接收日期当成起飞日期。

索引的起终点时间只是接收边界，均明确标记为观测时间；出发日期用实际观测起点机场当地时区校验。巡航中才开始接收、多机场候选、缺少端点时不猜测机场；不能确认当地出发日期或同日有多个实际航段时列出候选供选择。季度边界查相邻文件并按呼号、飞机和起终点去重。保留 MrAirspace 来源、观测边界和候选机场证据，并注明 ODbL-1.0；航司代码表来源为 [OpenFlights](https://openflights.org/data.php)。共享航班号或战术呼号没有可解析别名时仍可能无匹配。

FR24 或 ADS-B 有有效轨迹时，航班记录只保存该在线来源的原始点；同时按日期、机场和时间位置证据关联本地 GPS 原始点范围。原始 GPS 记录、点位和字段完全保留，预览及地图显示在线点与对应 GPS 点的并集，不插值补点。仅筛选航班时也显示关联 GPS，同时选择 GPS 原记录不会重复加入这些点；点位详情标明来源。GPS 来源删除或点列变化后旧引用失效。同航班、日期和机场唯一匹配已有记录时，预览提示更新原记录并保留 ID，避免重复导入；累计里程扣除仍由原始 GPS 覆盖的在线路段。

“我的旅程”中每个航班及航班详情的里程仅显示 FR24 航班摘要的 `actual_distance`（km），没有此值显示 `-.-`；按里程排序使用同一字段，未知里程排后。不以轨迹点累计距离或大圆距离代替。原始轨迹统计继续保留，用于地图和累计轨迹距离去重。

航班详情和资料预览中的起飞时间使用出发机场当地时区，落地时间使用实际到达机场当地时区（备降时优先实际机场），同时标注 UTC 时差；按航班日期自动处理夏令时。已有记录读取时自动补充机场时区，不改写原始 UTC 时刻。未知机场时区时明确标注 UTC 显示与时区未知，避免误用本机时区。

飞机资料和照片可独立于轨迹查询。注册号会去除空格并统一大小写，中文民航 `Bxxxx` 自动规范为 `B-xxxx`，越南民航 `VNAnnn` / `VNBnnn` 等规范为 `VN-Annn` / `VN-Bnnn`；注册号查询可自动取得 hex。轨迹查询失败时仍显示航班号、日期、机场以及已查到的呼号、起降时间、飞机资料和照片，可确认保存到“我的旅程”，轨迹留空；匹配已有航班时只更新资料，保留原 ID 和已有轨迹。本地 GPS 恢复成功时也保留已查到的资料。已有航班可通过“补充 / 更新航班信息”填写当日注册号，仅更新飞机资料及照片，不改变轨迹；飞机照片主地址失效时尝试缩略图，注册号照片查询也不依赖 hex。

本地恢复无需 hex。在线查询可填写当日注册号自动查 hex，或直接提供六位 ICAO24；有起飞时间时可绕过航班索引直接尝试单机历史轨迹。hex 只定位飞机，不能保证历史记录存在。adsb.lol 单机地址缺失不代表其完整归档没有数据；单机地址不可用时可以读取本机已检索的官方日归档单机缓存，校验来源、日期、hex 与 SHA256。使用呼号和已知飞行窗口识别零散观测，排除同机其他航班，缺口保留分段。本应用尚不会自动定位或下载数 GB 的整日归档。FR24 Explorer 的历史范围为 30 天，Essential 为两年，Tracks 接口自身最多三年；具体取决于套餐与覆盖。

航班使用官方 Flightradar24 API。点击左上设置，粘贴 API token，保存后输入航班号和出发当地日期。可以填写 IATA 或 ICAO 到发机场；同日多航段会要求选择。密钥不放在前端，不回显，不进入 CSV。也可以在项目 `.env` 中配置 `FR24_API_TOKEN`；网页设置优先。

无 API 密钥时，软件仍可使用 CSV 与铁路导入。FR24 网页会员与 API 订阅独立，完整轨迹最多约三年，并受套餐和覆盖限制。更早的快照采样本版未实现，以避免隐含的批量查询费用。没有位置记录就返回无数据。默认 API 存储条款仅允许接收后保存30天；本地长期存档以用户已有授权范围为准。[FR24 API](https://fr24api.flightradar24.com/)、[存储规则](https://fr24api.flightradar24.com/docs/storage-rules)


线路设计速度、运营限速、轨迹点观测速度分别保存；未知值留空，不能根据 G 字头或线路设计速度生成实测最高速度。

添加航班、车次或经由足迹后，从预览点击“返回修改”会保留已填信息。添加足迹已移除沙箱测试入口。经由线路存在几何缺口时，保存为同一足迹内的独立轨迹段，缺口不连线、不计里程，时间连续。

## 地图

MapLibre GL JS 与 OpenFreeMap 底图。轨迹按飞机、铁路、其他类型着色，只绘制原始点，不绘制连接线。当前筛选下全部点按本机矢量瓦片加载，不抽稀、不聚类，不删除重复坐标；选中一天时其他天的点继续显示并淡化。总览边界根据全部原始坐标计算；跨180度航班仍可正常定位。点位详情读取原始坐标、时间、高度和速度。密集点在小比例尺下可能互相覆盖，放大可查看点间缺口。底图联网加载，个人轨迹本地保存。底图服务不可达时仍能显示轨迹，提供重试入口；本版未打包离线底图。[MapLibre](https://maplibre.org/)、[OpenFreeMap](https://openfreemap.org/)

## 高度与速度图

选中一条轨迹，在详情卡片中点击“高度与速度图”，可同时查看这条轨迹某一天的高度—时间和速度—时间曲线。跨天轨迹可以选择有记录的日期，切换本机时区或 UTC；两幅图使用相同的时间范围。默认放大有效记录时段，也可切换为全天。悬停、触摸或使用键盘可查看记录点的时间与数值。

高度单位为米，速度单位为 km/h。FR24 高度明确标注为气压高度，速度来自地速记录。图表使用本地已保存的数据，不额外查询 API。没有时间或对应指标的数据会显示提示；不会以线路设计速度填充观测值。缺失指标、来源区段切换、时间倒退及超过 15 分钟的间隔会断开曲线，单个有效点仍可显示。导出的 CSV 保留原始完整点列，图表为显示而做的降采样不影响保存或导出。

### 完整下载历史航班索引

在项目目录运行 `.venv/bin/python scripts/download_flight_indexes.py`，默认下载 2024Q1 至 2026Q2，逐季度优先详细版，复用应用的 `data/flight_schedules` 缓存。已有完整缓存自动跳过，部分文件断点续传，网络失败自动重试；Ctrl+C 终止后可运行同一命令继续。文件发布前校验长度和 Parquet 格式，官方提供 SHA-256 时同时校验摘要。不会读取或修改航班和 GPS 记录。

仅查看大小：`.venv/bin/python scripts/download_flight_indexes.py --list`。指定季度：`--from 2025Q1 --to 2025Q4`。当前目录所列 10 个文件共 6,384,516,912 字节（6.385 GB / 5.946 GiB），目录更新后大小以脚本输出为准。索引是历史观测汇总，下载成功不保证每趟航班都有完整日期、机场或飞机资料。

下载脚本的目录请求、文件请求及重定向均使用 `trust_env=False`，忽略系统和环境变量中的 HTTP / HTTPS / SOCKS 代理。每秒输出百分比、已下载／总大小、当前下载速度和预计剩余时间，标准输出即时刷新。FlClash 的 TUN 属于系统路由，若启用仍需在 FlClash 内关闭 TUN 或设置相应直连路由；脚本不修改代理软件设置。

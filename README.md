# 足迹 Footprint

在本机保存、浏览和导出个人轨迹，支持飞机、铁路及其他自行导入的足迹。网页界面与 SQLite 数据库均在本机运行。

## 主要功能

- **轨迹导入与导出**：支持一生足迹备份、通用 CSV 和 FR24 CSV，可匹配列名与选择坐标系。
- **地图与记录浏览**：显示全部原始轨迹点，支持日期、类型筛选、关键词搜索及逐点详情。
- **高度与速度图**：按日查看已保存轨迹的高度、速度与时间变化。
- **铁路足迹**：自动匹配已到达线路和区间，支持手动维护；也可按车次、日期与到发站查询并重建乘车区间。
- **航班足迹**：查询航班资料与可用的实际轨迹，支持从已有 GPS 恢复航段，以及补充飞机资料与照片。

铁路重建线路与实际 GPS 轨迹分别标注；缺失的轨迹、时间和测量值不会补造。在线查询结果取决于来源的覆盖范围。

## 安装与启动（Windows / Linux / macOS）

需要 **Python 3.11+**、**Node.js 22.12+（含 npm）**。首次安装需要联网；源码应放在当前用户可写的目录中，以普通用户运行。Windows 安装 Python 时需加入 PATH；Linux 需安装 Python 的 venv 支持。

在项目根目录执行：

```sh
npm start
```

首次启动自动创建 `.venv`、安装依赖并构建前端，随后启动服务、打开浏览器。也可使用系统入口：

| 系统 | 启动方式 |
| --- | --- |
| Windows | 双击 `start.bat` |
| Linux | `sh ./start.sh` |
| macOS | 双击 `start.command` 或运行 `sh ./start.sh` |

默认地址为 `http://127.0.0.1:8765`，端口被占用时尝试 8766，以终端输出为准。保持终端打开，按 Ctrl+C 停止。服务仅监听本机地址。

更新源码或依赖后，重新安装并构建：

```sh
npm start -- --setup
npm start
```

使用 `npm start -- --no-open` 可禁止自动打开浏览器。Windows 若提示 `npm.ps1` 被阻止，可使用 `npm.cmd` 替代 `npm`。

## 数据与配置

- **导入 CSV**：默认采用一生足迹的 11 列格式，示例见 [CSV 模板](examples/track-template.csv)。时间为 Unix 秒，速度为米/秒，高度为米；通用 CSV 的速度为 km/h，FR24 单位自动转换。导入 GCJ-02 数据时需选择对应坐标系，导出统一为 WGS84。
- **铁路目录**：自动铁路匹配前需准备公共目录，安装与启动不会自动下载大型数据。下载方式及可选航班索引见 [数据准备指南](docs/data-sources.md)。手动维护见 [铁路足迹操作说明](docs/rail-manual-editing.md)。
- **航班 API**：在网页设置中保存 Flightradar24 API token，或在 `.env` 中配置 `FR24_API_TOKEN`，网页设置优先。FR24 网页会员与 API 订阅独立；历史范围、查询费用和数据保存期限以服务方授权为准。未配置密钥仍可导入 CSV 和铁路记录。
- **本地存储**：默认数据库为 `data/footprint.sqlite3`，网页保存的密钥位于 `data/settings.json`。备份时复制整个 `data/` 目录；使用 `.env` 时另行备份该文件，并妥善保管密钥。
- **自定义位置**：启动前设置 `FOOTPRINT_DATA_DIR` 可更换数据目录，设置 `FOOTPRINT_PORT` 可指定端口。

底图与在线查询需要联网，个人轨迹保存在本机。仓库只包含源码、依赖清单、配置示例和公共数据源说明，不包含个人轨迹、数据库、密钥或下载缓存；首次使用需自行导入数据或恢复备份。
